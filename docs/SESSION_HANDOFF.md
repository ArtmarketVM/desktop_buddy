## Working change: capture diagnostics and window-capture hardening — 29 October 2026

Branch `fix/window-capture-diagnostics`, rebased onto `origin/main` `db0dd14` (released 0.49.3). Version 0.49.4; notes in `docs/RELEASE_0.49.4.md`. Started from Vladislav's handoff about `capture_unavailable` on Windows before 0.49.1 shipped its own Windows Graphics Capture path; the rebase keeps the 0.49.1 behaviour and layers the following on top.

- **Diagnostics** (`src-tauri/src/vision.rs`): typed `CaptureFailure { kind, detail }` replaces the string-to-status mapping. `screenshot_status` carries the category, the new `screenshot_detail` the platform stage (Personal AI Engine panel, `observation::capabilities`, `--check-observation-workflow --native-fixture`). Details are a closed vocabulary of static identifiers.
- **Windows** (`src-tauri/src/vision/windows.rs`, `vision/geometry.rs`): Windows Graphics Capture remains the primary path. Added: capture border and cursor suppression (`GraphicsCaptureAccess` borderless request, tolerated when refused), client-area crop only when the frame maps 1:1 onto `GetWindowRect`/DWM frame bounds, uniform-frame rejection (`blank_frame`), `window_minimized`, DWM-cloaked and display-affinity checks, bounds re-check after capture, `E_ACCESSDENIED` → `permission_unavailable`, and a guarded GDI fallback for systems without the API (pre-1903) that still rejects any other application's visible window above the client area (own-process and cloaked windows exempt; policy in `geometry.rs` with tests). The interactive native regression from 0.49.1 (`vision/windows/native_tests.rs`, ignored, synthetic windows only) is adapted to the typed failures.
- **macOS** (`src-tauri/native/macos.m`, `src-tauri/src/macos.rs`): the focused Accessibility window is resolved to a `CGWindowID` front to back (same owner, layer 0, bounds ±1 pt; matching title breaks ties), then matched to the `SCWindow` by ID. Minimized, closed and unresolved (zero-hash) identities get their own categories; the focused window identity and bounds are re-checked after the screenshot (title drift tolerated). `capture_window_selection.h` stays for `context_test.m`. Local fixture/probe for live verification: `scripts/fixtures/capture-fixture.m`, `capture-probe.m` (build commands in their headers; needs an unlocked session).

Local evidence on the rebased source (Apple Silicon): `cargo test --locked` 773 passed / 5 ignored (766 baseline + 7 new); debug `cargo clippy --locked --all-targets -- -D warnings` and `cargo fmt --check` pass; `npm test` 347 passed (a first run concurrent with the Rust build timed out 9 timing-heavy files; the isolated rerun passed all); `tsc -b`, ESLint 0, Knip 0, `npm run test:release` 20 passed, `npm run build` ok; `prepare-release.mjs --check` verified five synchronized manifests. The Windows module and its native test were type-checked and clippy-clean for `x86_64-pc-windows-msvc` from this Mac; the new border/crop/blank-frame/fallback paths were not run on a Windows desktop, and release-profile Clippy runs only in CI (no local `cmake`). The macOS live overlay probe still needs an unlocked session.
